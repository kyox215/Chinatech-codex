# capability-review

## 目标

让 Agent 能力基于可复现实绩逐步进化，同时把知识、能力、权限和自治四者严格分开。

## 输入

- 任务结果与证据
- Agent 工作包表现
- 失败/返工
- 现有 Capability Registry
- QA/Security 结论

## 执行流程

1. 按工作包收集证据：正确性、独立性、复杂度、复现性、审查结果、返工和边界遵守。
2. 区分 Knowledge（知道）、Capability（已验证能做）、Permission（允许做）和 Autonomy（可自主到哪）。
3. 判断证据是否跨任务可泛化；一次偶然成功只形成候选，不直接升至 C3/C4。
4. 为 Skill 或 Agent 提出改进：触发描述、步骤、检查表、测试、工具或限制；避免自我修改即生效。
5. 若建议升级，定义沙箱评估、成功阈值、反例、QA/安全审查、灰度范围和撤销条件。
6. 记录降级条件：重复错误、越界、过期技术、工具变化、审计失败或安全事件。
7. 只有指定批准人可以变更 Permission/Autonomy；Capability Auditor 仅提供证据和建议。

## 必须产出

- 能力评估
- C0–C4 建议
- Skill 改进提案
- 评估用例
- 升级/降级/撤销条件

## 门禁与停止条件

- Agent 不得自称“已学会”作为证据
- 能力升级不等于权限升级
- 禁止根据输出流畅度评估能力

## 记忆更新

更新 CAPABILITY_REGISTRY、Agent profile 和提案记录；保留批准状态。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
