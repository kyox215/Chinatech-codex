# task-closeout

## 目标

只有在结果可证明、残余风险有 owner、长期知识已处理时，任务才从“做完代码”转为治理意义上的完成。

## 输入

- 任务验收标准
- diff/提交
- QA/安全/发布结论
- Memory Delta
- 开放风险和批准

## 执行流程

1. 逐条核对验收标准并引用证据；不可验证项标记失败或有条件，不用模糊语言。
2. 确认范围内工作完成、范围外工作未偷偷混入，工作区无意外改动和敏感信息。
3. 汇总测试、安全、数据迁移、发布和文档状态；说明未运行或不适用的理由。
4. 处理所有开放项：解决、转独立任务、获得风险接受或明确阻塞；不得让“以后看看”无 owner。
5. 运行 `$memory-consolidation`、`$department-memory-sync` 和必要的 `$capability-review`。
6. 生成 CEO 报告：业务结果、变更、证据、风险、操作说明、回滚、后续任务和决策请求。
7. 把状态设为 closed/conditional/blocked，更新 ACTIVE_CONTEXT；保留可恢复档案。

## 必须产出

- 验收矩阵
- 最终 CEO 报告
- 残余风险与后续任务
- 记忆/能力变更
- 关闭状态

## 门禁与停止条件

- dirty 状态未处理不得无条件关闭
- 高风险发现未接受不得 PASS
- “看起来正常”不是证据

## 记忆更新

关闭 TASK，更新 ACTIVE_CONTEXT、索引、长期记忆、部门和能力登记。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
