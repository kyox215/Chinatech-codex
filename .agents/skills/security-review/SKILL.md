# security-review

## 目标

基于威胁路径检查真实信任边界和服务端控制，优先发现可利用的权限、数据和供应链问题。

## 输入

- 任务/PRD
- 代码 diff 和调用链
- 数据分类
- 身份、权限、日志与部署配置

## 执行流程

1. 建立轻量威胁模型：资产、攻击者、入口、信任边界、滥用场景和最坏影响。
2. 检查认证生命周期、服务端授权、对象级访问、租户隔离、默认拒绝和管理员路径。
3. 检查输入验证、输出编码、注入、文件上传、SSRF、重定向、反序列化和资源耗尽。
4. 检查秘密来源、日志/错误泄露、客户端暴露、依赖与 CI/CD 供应链。
5. 检查审计事件是否记录 actor、action、target、result、time、request/context，且不记录敏感正文。
6. 为每个发现给出严重性、证据、攻击路径、前置条件、影响、修复和验证；区分已证实与潜在。
7. 高风险修复后独立复测；未解决发现必须有 owner、期限和正式风险接受人。

## 必须产出

- 威胁模型
- 按严重性排序的发现
- 证据和复现
- 修复/缓解
- 安全门禁结论

## 门禁与停止条件

- 客户端隐藏不算授权
- 未验证不能声称无漏洞
- Reviewer 默认不修改被审查代码

## 记忆更新

沉淀可复用安全规则与已知风险；漏洞敏感细节按最小知情范围保存。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
