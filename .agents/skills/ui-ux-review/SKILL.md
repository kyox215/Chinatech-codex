# ui-ux-review

## 目标

让相同业务含义使用相同控件、状态表达和编辑方式，布局按手机、iPad、桌面分别适配。沿用现有 Next.js、Radix/shadcn、Tailwind 和 RepairDesk 视觉体系。

## 项目来源与按需路由

- 在仓库根解析以下路径。视觉说明读 `docs/DESIGN_SYSTEM.md`；实际颜色值只来自 `src/styles.css`。布局类复用 `src/lib/ui-patterns.ts`，控件/弹层类复用 `src/lib/component-patterns.ts`；不要另外生成一套 DESIGN.md 或 token 字典。
- 页面结构变化读 `docs/UI_PAGE_GENERATION_DECLARATION.md` 和 `docs/RESPONSIVE_DENSITY_PLAN.md`；组件变化读 `docs/COMPONENT_GENERATION_DECLARATION.md`；编辑交互读 `docs/GLOBAL_CONTENT_EDITING_STANDARD.md`；手机详情读 `docs/REPAIROS_MOBILE_DETAIL_STANDARD.md`。
- 全站一致性或跨页面整理读 `docs/PROJECT_EXECUTION_ROADMAP_2026-09-04.md` 的 `ui-consistency-20260912` 节。它记录最新用户要求与旧规范冲突；不要把历史候选合同误当成当前全站默认。
- 使用已安装的 `ui-design-workflow` 执行设计/视觉工作；模型要求遵循适用 AGENTS 和该技能的实际运行要求，不以文字声称切换档位。
- 外部方法按任务选择：Impeccable 的 Operate/audit/polish/harden 用于一致性和边界检查，Vercel Web Interface Guidelines 用于代码位置明确的交互/a11y检查。来源及筛选结论见路线图；未安装不得声称运行外部命令。

## 输入

- PRD/用户流程
- 设计系统与现有组件
- 目标设备与可访问性要求
- 真实数据形态和权限

## 执行流程

1. 确认页面任务、主要用户、首要动作和信息层级；删除无业务价值的装饰和重复信息。
2. 先用 `rg` 定向查找真实组件、调用处及对应 stories/tests，记录“复用 / 扩展 / 确需新建”。优先复用 `src/components/ui/*`、`src/components/orders/badges.tsx`、`FaultDiagnosisPicker`、`MoneyKeypadInput` 和现有设备解锁编辑器；核实导出和 props 后再引用。新变体明确职责、尺寸、状态和键盘行为，避免把业务条件塞进通用控件。
3. 覆盖默认、加载、骨架、空、错误、无权限、离线、部分成功、长内容和极端数据状态。
4. 同一套 tokens、控件语义和领域数据服务三端；桌面与 iPad 优先共享工作台结构，并按可用宽高、触控和键盘调整分栏/导航/操作位置。手机保持既有操作链与独立单列布局。断点按内容验证，不用 UA 或某个宽度直接推断设备，避免旋转时重挂载编辑器。
5. 检查可访问性：语义、标签、焦点、键盘、错误提示、颜色非唯一编码和动态内容公告。
6. 对删除、退款、取消、覆盖、批量等危险动作定义确认、影响预览、撤销或恢复。
7. 把交互说明映射到组件、数据需求、埋点和 UI 验收步骤。
8. 一致性整改从一个完整故事开始：新建工单或详情报价编辑。先验证真实页面，再推广同一组件的调用方。只改视觉时保留 mutation、权限、版本冲突、金额、状态和审计语义；发现缺陷单列证据，不借统一 UI 自动改变保存策略。
9. 编辑器 header/body/footer 的结构统一，尺寸按简单选择、普通编辑、复杂工作台分档；关闭和提交可达、正文单一主滚动。保留已有会话与虚拟键盘宿主，先修复可复现问题，再评估公共抽象，不先建立万能全局弹层状态机。
10. 以当前界面语言显示一份标签；zh/en/it 长文本、金额日期格式和错误提示一起检查。品牌/型号大写沿用已批准字段规则，不扩大到客户姓名、备注或密码。手势操作保留点击与键盘替代。
11. 核查 token 最终计算样式、Provider 和 Portal 挂载，而非只检查 class 名。按适用范围检查加载/空/错误/禁用/选中/焦点，记录命中位置和用户后果；历史差异与新增回归分开，打印/图表/相机等有意例外需注明理由。

## 必须产出

- 页面/组件结构
- 交互与状态表
- 响应式规则
- 可访问性要求
- UI 验收清单

小改把上述内容精简到任务答复；重要改版复用路线图或既有设计文档，不按每次对话新增日志。纯计划只交付计划，不把截图或测试写成已完成。

## 验证范围

- UI 实施检查代表手机、iPad 竖/横屏和桌面；具体视口、语言与故事按路线图选择。截图验证布局，实际点击/输入/保存/重开验证行为，两者不能替代。
- 重点覆盖长译文、短高度、键盘开关、旋转、失败重试、放弃草稿、关闭返回焦点及金额汇总；涉及哪些就验证哪些，不为文案小改跑完整笛卡尔积。
- 结构或行为修改运行对应组件/领域测试；共享模块迁移与发布候选按项目门禁扩大验证。仅文档/技能变化做规则、链接和技能结构检查，明确无新增页面可截图。

## 门禁与停止条件

- 不得只交付正常截图状态
- 无权限与错误不能泄露敏感信息
- 危险操作必须体现后果和恢复路径

## 记忆更新

稳定设计模式进入 design/frontend 部门记忆；任务特定画面保留在任务文档。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。
