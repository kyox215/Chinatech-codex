# risk-autonomy-classify

## 目标

用统一模型决定 Agent 可以自主做到哪里、何时必须审批，以及需要哪些独立审查和回滚证据。

## 输入

- 任务章程
- 数据/权限/生产/财务/法律影响
- 可逆性和爆炸半径
- 现有审批与自治政策

## 执行流程

1. 分别评估用户影响、数据完整性、安全隐私、生产可用性、财务法律、外部系统、供应链和声誉风险。
2. 评估可逆性：回滚时间、备份有效性、迁移兼容性、是否有不可撤销外部行为。
3. 按最高影响确定 R0–R4，而不是取平均；不确定时采用更高一级直到证据降低风险。
4. 根据风险、任务清晰度、能力登记和工具权限确定 L0–L4；R3/R4、生产写入和不可逆操作默认降级。
5. 标记 D1/D2 可自行决定项与 D3/D4 保留决策，形成具体批准点而不是笼统“全程等待”。
6. 为每个批准点定义所需材料：选项、收益、风险、成本、验证、回滚、最晚决策时间。
7. 范围、目标、目标环境或失败模式改变时重新分类并记录原因。

## 必须产出

- 风险矩阵
- 风险等级与理由
- 自治等级与边界
- 审批点和批准包
- 强制审查角色

## 门禁与停止条件

- 权限模型、生产、支付、敏感数据不得按普通低风险处理
- 无可验证回滚不等于可逆
- Agent 能力等级不能自动扩大业务授权

## 记忆更新

把分类、理由、批准人和复审触发条件写入 TASK.md 与 ACTIVE_CONTEXT。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
