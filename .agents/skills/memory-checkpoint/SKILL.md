# memory-checkpoint

## 目标

把当前可观察状态压缩成下一会话可继续的最小充分记录，而不是保存完整聊天或思维过程。

## 输入

- 当前任务
- Git diff/状态
- 实际测试证据
- 决定、风险、阻塞和下一步

## 执行流程

1. 确认任务 ID、阶段、工作区状态和最后检查点；不要在错误任务目录写入。
2. 记录已完成和未完成，引用文件/提交/测试/日志证据；区分事实、推断和计划。
3. 记录关键决定、替代方案、理由、批准状态、影响和需要长期 ADR 的候选。
4. 记录开放风险、冲突、阻塞、owner、解除条件和最晚处理点。
5. 给出下一步的可执行首个动作、输入、停止条件与需要读取的文件。
6. 使用 CLI：`python tools/ai_company.py checkpoint --task ... --summary ... --next ...`，或按相同结构原子更新。
7. 检查点完成后清除 dirty 标记；但这不代表 QA、安全或发布门禁已通过。

## 必须产出

- 时间戳检查点
- 证据引用
- 决定与风险
- 下一步
- 更新后的 ACTIVE_CONTEXT

## 门禁与停止条件

- 不保存隐藏思维链、秘密或完整命令正文
- 不把计划写成已完成
- 无证据的“测试通过”禁止记录

## 记忆更新

追加 CHECKPOINTS.md，更新 ACTIVE_CONTEXT 和 runtime checkpoint 状态。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
