# handoff-resume

## 目标

让接手者无需重读全部历史即可知道目标、事实、进度、风险、证据和下一动作，并能识别过期内容。

## 输入

- 当前检查点
- 任务/Context Packet
- diff 和测试
- 开放决定、风险、阻塞

## 执行流程

1. 交出方记录任务目标、当前阶段、完成项、未完成项、工作区/分支状态和最后验证时间。
2. 列出必须知道的约束、批准边界、关键决定及来源；不要复制全部讨论。
3. 列出变更文件、未提交内容、运行环境、测试命令与真实结果，以及不能安全重跑的操作。
4. 记录开放风险、失败尝试、未知项和下一步第一动作；明确不要重复的危险操作。
5. 接手方执行 Resume：核对文件/分支/任务 ID、抽样验证高影响事实、检查新 diff 和过期时间。
6. 接手方确认接受、拒绝或要求补充；未验证的交接内容保持 observed/inferred。
7. 恢复后创建新检查点，记录上下文差异和重新分类结果。

## 必须产出

- Handoff Packet
- Resume 验证报告
- 上下文差异
- 明确第一动作和停止条件

## 门禁与停止条件

- 交接不是批准
- 不能只写“看上面的聊天”
- 未提交代码和不可逆操作必须显式标注

## 记忆更新

更新 HANDOFF.md、CHECKPOINTS.md、ACTIVE_CONTEXT 和相关 Agent/部门状态。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
