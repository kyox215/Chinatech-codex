# implementation-control

## 目标

让 `implementer` 在明确边界内完成可审查、可回滚的变更，并防止无关重构或虚假完成。

## 输入

- 已批准计划
- 文件范围与验收标准
- 相关 Agent 结论
- 测试命令和回滚要求

## 执行流程

1. 实施前再次确认工作区状态，区分用户已有改动、任务改动和生成文件；不得覆盖不明改动。
2. 逐个工作包实施，优先最小、可逆、符合现有约定的方案；不为“顺便优化”扩大范围。
3. 保持类型、校验、错误处理、权限和日志在正确层；前端不承担服务端授权。
4. 每个可验证增量后运行最窄相关测试，再逐步扩大到模块和回归测试；记录实际命令与退出结果。
5. 发现计划错误、隐藏耦合或风险升级时停止写入，创建 Plan Delta，不用补丁堆叠掩盖问题。
6. 实施结束检查 diff：意外文件、调试输出、密钥、生成噪声、格式化扩大、迁移顺序和兼容性。
7. 创建检查点，把已完成、未完成、测试、风险和待 Reviewer 复核项交给主线程。

## 必须产出

- 最小代码变更
- 变更文件清单
- 真实测试结果
- 偏差/限制
- 回滚说明

## 门禁与停止条件

- 只有一个默认业务代码写入者
- 测试未运行必须明确说明原因
- 实施 Agent 不自行批准高风险例外

## 记忆更新

实施后运行 `$memory-checkpoint`，但稳定长期知识由后续 consolidation 决定。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
