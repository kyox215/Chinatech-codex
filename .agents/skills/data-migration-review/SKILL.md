# data-migration-review

## 目标

确保数据变更具有约束、兼容、可观测和恢复策略，不因代码“能跑”而牺牲数据完整性。

## 输入

- 现有 schema/迁移历史
- 业务规则与数据量
- 读写路径
- 备份、恢复和停机限制

## 执行流程

1. 验证当前表、字段、约束、索引、外键、枚举和主要查询路径，引用真实 schema。
2. 定义目标模型及不变量：唯一性、非空、引用完整性、金额/时间精度、租户隔离和审计字段。
3. 评估锁、表重写、索引构建、事务大小、复制延迟、长事务和容量增长。
4. 采用 expand/migrate/contract：先兼容新增，再回填与验证，最后在安全窗口收紧或删除。
5. 设计幂等、可暂停、可重跑的回填；定义批量大小、游标、失败隔离、进度和校验查询。
6. 定义备份与恢复演练、回滚限制、旧版本兼容窗口和数据验证阈值。
7. 任何删除、不可逆转换或生产执行都生成批准包与运行手册。

## 必须产出

- Schema 变更设计
- 迁移/回填步骤
- 性能与锁风险
- 数据校验
- 回滚/恢复方案

## 门禁与停止条件

- 先删字段再发布兼容代码禁止
- 无生产数据量评估不得声称迁移安全
- 备份存在不等于恢复已验证

## 记忆更新

更新 data 部门记忆、迁移记录、TASK 的 EVIDENCE 和 DECISION_INDEX。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。
