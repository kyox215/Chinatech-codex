# memory-consolidation

## 目标

把高价值、可复用、可验证知识从任务记忆提升到长期层，同时控制陈旧、重复和错误传播。

## 输入

- 任务 MEMORY_DELTA
- 检查点与证据
- 现有项目/部门记忆
- 冲突和替代关系

## 执行流程

1. 收集候选：新业务规则、架构决定、接口契约、SOP、风险、反模式、运行知识和能力证据。
2. 逐条判断是否长期有用、是否超出单任务、是否有来源、owner、作用域和复审条件。
3. 与现有记忆去重；新信息冲突时创建 disputed 记录，不静默覆盖旧事实。
4. 给候选分配状态：observed、verified、approved、proposed、superseded、expired，并保留来源。
5. 写入正确层：项目、部门、ADR/决定、Lesson 或 Capability；不要把所有内容塞进 PROJECT_MEMORY。
6. 更新索引、反向链接、替代关系和最后验证时间；归档只保留必要证据路径。
7. 执行敏感信息检查和上下文预算检查；对大段原文只存摘要与来源，不复制。

## 必须产出

- Memory Change Set
- 更新后的长期记忆
- 冲突/过期项
- 未提升的临时项及理由

## 门禁与停止条件

- 候选经验不能自动成为批准制度
- 摘要必须保留来源
- 个人数据和秘密遵循最小化原则

## 记忆更新

更新 MEMORY_INDEX、PROJECT/DEPARTMENT/DECISION/LESSONS/CAPABILITY 对应文件。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
