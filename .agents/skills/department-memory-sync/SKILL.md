# department-memory-sync

## 目标

让每个部门随着项目推进更新自己的事实、在制工作、接口、经验和能力，而不是共享一个混乱总摘要。

## 输入

- 任务 Memory Delta
- 受影响部门
- 部门现有记忆
- 架构/产品/QA/安全结论

## 执行流程

1. 识别真正受影响的部门；只读相关部门文件，避免无意义全组织更新。
2. 更新部门使命/边界仅需正式组织决定；普通任务主要更新规则、接口、SOP、风险、经验和当前重点。
3. 记录跨部门输入/输出契约：提供方、消费方、格式、SLA、失败处理和变更通知。
4. 对新增经验区分一次性修复、候选模式和已验证标准；需要多次证据的保持 proposed。
5. 更新技术债、风险、owner、期限和复审触发；已解决项归档但保留链接。
6. 同步该部门 Agent 的能力证据，但不自动提升权限和自治。
7. 检查与 PROJECT_MEMORY、ADR 和其他部门记录的一致性，冲突进入 OPEN_CONFLICTS。

## 必须产出

- 部门 Memory Delta
- 更新后的部门记忆
- 跨部门契约变化
- 风险/能力候选

## 门禁与停止条件

- 部门 Agent 不能自行重写公司宪法
- 一次成功不等于成熟能力
- 跨部门接口变更必须通知消费者

## 记忆更新

写入 `.ai-company/memory/departments/<department>.md` 与相关索引。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
