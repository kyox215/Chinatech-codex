# documentation-sync

## 目标

确保不同读者能用文档正确开发、操作、支持和恢复系统，同时避免复制易过期信息。

## 输入

- 代码 diff
- 任务与决定
- 现有 README/API/schema/runbook
- 目标读者和验证方式

## 执行流程

1. 识别受影响读者：用户、开发、QA、运营、支持、安全、SRE 或新成员。
2. 建立变更到文档映射，优先更新权威来源；其他文档引用而不是复制完整规则。
3. 更新安装、配置、命令、API 示例、迁移、权限、故障排除、发布和回滚等实际步骤。
4. 运行或手工验证关键命令和示例；不能验证时标记环境与限制。
5. 删除或标记过期内容，维护版本/最后验证时间/owner；重大决定链接 ADR。
6. 检查秘密、内部 URL、个人数据和客户信息泄露；公开文档采用最小披露。
7. 在任务证据中列出已更新、无需更新及待后续处理的文档。

## 必须产出

- 文档影响矩阵
- 更新后的权威文档
- 验证结果
- 过期/缺失清单

## 门禁与停止条件

- 代码变更完成不代表文档无需更新
- 示例不能包含真实密钥
- 文档不得与正式 schema/接口冲突

## 记忆更新

更新 documentation 部门记忆、文档索引和最后验证时间。

## 通用执行约束

- 先读当前目录适用的 `AGENTS.md` / `AGENTS.override.md`。
- 只加载与任务相关的政策和记忆；避免把整个制度包塞入上下文。
- 对事实附文件、符号、测试、日志或正式决定证据；不把推断写成事实。
- 遵守单一写入者、最小权限、可逆优先、秘密最小化和不覆盖用户改动。
- 当范围、风险、目标环境或关键假设变化时，暂停并重新分类。

## 建议输出格式

```markdown
# 结论
# 已验证事实与证据
# 假设 / 未知 / 冲突
# 决策或建议
# 风险与审批点
# 验证结果
# Memory Delta
# 下一步
```
