# Task

## Owner goal

为每个仍存在的维修订单提供一个固定二维码；未登录扫码显示客户公开维修进度，已登录且通过店铺、角色和对象权限检查时打开内部订单详情。任何订单业务状态都允许打开打印窗口，且打印文档必须包含该订单二维码。完成后推送 `main` 并部署生产。

## Scope

- 固定订单二维码的数据模型、历史回填、约束与兼容解析。
- 客户公开查询与已登录员工自动内部跳转。
- 订单详情、任务页、列表单张与批量打印。
- 作废、取消、完成、历史状态的打印表达；永久不存在的记录不在范围内。
- 权限、租户隔离、限流、日志最小化、测试、声明、发布和回滚。

## Constraints

- 同一个二维码根据有效登录和服务端授权决定公开视图或内部详情；未登录员工与客户行为相同。
- 不增加公开 PII，不在二维码中放客户资料、IMEI、密码或内部订单 UUID。
- 打印不得依赖临时二维码签发；店铺资料、二维码开关或订单业务状态不得禁用打印。
- 服务端继续执行同店、角色、`order:detail` 和 Technician assignment 校验。
- 兼容已经打印的旧随机二维码；禁止破坏旧票据解析。
- 当前工作区包含多个已验证但未提交任务，必须按文件和 hunk 隔离，禁止覆盖不明改动。

## Acceptance criteria

1. 每个非物理删除订单都有唯一稳定二维码身份，新订单自动具备，历史订单覆盖率为 100%。
2. 未登录扫码直接显示安全公开维修进度，不提供员工登录分支。
3. 已登录且有权限时自动进入内部订单详情；跨店、无权限、Technician 非本人订单回落到公开视图。
4. 所有订单业务状态都可打开打印窗口；每张打印页严格包含一个对应二维码。
5. 单张、批量和重复打印不再轮换二维码，不依赖打印时数据库写入。
6. 旧二维码继续解析；店铺生命周期变化、手动安全重置和权限边界保持有效。
7. lint、typecheck、相关测试、完整测试、build、浏览器与实体扫码/打印验证通过。
8. 项目声明、迁移说明、监控和回滚文档与实际行为一致。

## Execution plan

1. 只读探索和 DATA/SEC 独立审查，锁定兼容模型。
2. Expand migration 与服务端双解析/固定链接读取。
3. 客户页自动身份分流和全部打印入口接入。
4. 定向测试、全量质量门禁、浏览器/打印视觉证据。
5. 生产迁移、提交推送 `main`、部署、生产冒烟与回滚验证。

## Agent plan

- `fixed_qr_explorer`：只读现状与冲突地图。
- `fixed_qr_data`：只读 schema、回填和迁移审查。
- `fixed_qr_security`：只读授权、隐私和威胁模型。
- 主线程为唯一写入者、集成者和发布执行者。
- 实施完成后另起只读 QA 复核。

## Rollback

- 应用可回退到旧随机二维码解析与打印路径；新增 schema 保留，不执行破坏性 down migration。
- 新二维码解析必须在新签发启用前部署；关闭新路径时继续解析已打印固定二维码。
- 生产异常时优先前滚修复或关闭固定链接发放，不删除历史 token、订单或迁移数据。

## Visual evidence

- 必须覆盖公开客户状态页、已登录内部跳转、桌面打印预览、批量打印和至少一个结束/作废状态打印。
- 截图不得包含完整客户 PII、二维码原始 token 或生产凭据。
