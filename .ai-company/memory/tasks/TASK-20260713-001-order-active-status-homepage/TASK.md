# Task - 订单首页进行中状态分层与终态隐藏

## Owner request

按照已确认计划实施：订单待处理首页不显示完成和作废，继续显示下单、到货、到货已通知、修好和修好已通知并用明显层级标签和指定颜色区分；移动端状态筛选不得横向滑动；完成验证后推送 `main`。

## Business value

让前台和维修人员首页只看仍需行动的订单，消除大量终态历史记录造成的 117 页噪音，同时确保仍在店内或仍处于配件、维修、通知阶段的设备不会漏单。

## Scope in

- 全局默认待处理列表以订单终态为准：`completed` 和 `cancelled` 不进入默认待处理首页。
- 所有其他非终态订单保持可见，不因付款、交付或异常字段被隐藏。
- 服务端在分页和计数前应用同一可见性规则，并保持 mock/API 一致。
- 将进行中订单按处理中、下单、到货、到货已通知、修好、修好已通知分层。
- 订单卡片显示文字、图标和颜色共同编码的阶段标签。
- 移动端采用固定/换行网格，禁止横向滑动状态栏和页面横向溢出。
- 完成/作废订单保留在历史和授权搜索中，不删除、不改写生产数据。
- 保持现有单笔金额可见与历史聚合/批量导出权限边界。

## Scope out

- 生产数据修复、删除、迁移或 SeaTable 再导入。
- 设置中心任务、仪表盘新设计、角色权限扩张或部署生产环境。
- 更改订单状态转换、付款数据、客户数据、设备数据或通知发送行为。
- 新增依赖、重构无关订单详情或修改其他店铺数据。

## Hard constraints

- 移动端状态筛选不得使用横向滚动、轮播或滑动容器。
- 颜色不能作为唯一状态信号；必须保留清晰文字和图标。
- 服务端查询必须先过滤再计数/分页，不能只在客户端隐藏。
- 共享脏工作区和暂停的 Settings Center 工作树保持不动。
- 仅在完整验证和独立复核通过后推送 `main`。

## Plan delta

上一任务采用“终态 + closed + delivered + exactly paid 才归档”的保守责任规则。老板本次明确决定首页展示只以终态为准：完成和作废无条件离开默认待处理列表；交付、付款或资料矛盾移入历史/授权异常筛选，不得把终态订单重新拉回首页。历史数据本身不修改。

## Acceptance criteria

- [x] 任意 `completed` 订单均不出现在默认待处理列表，不受付款或交付字段影响。
- [x] 任意 `cancelled` 订单均不出现在默认待处理列表。
- [x] 所有非终态订单继续出现在默认待处理列表。
- [x] 下单为蓝色；到货/到货已通知为黄色；修好/修好已通知为绿色，并有文字与图标。
- [x] 默认总数等于各进行中分组之和，页数基于过滤后结果。
- [x] 完成/作废仍可在历史和既有授权搜索中查看。
- [x] 320、390、430 像素移动端无横向状态栏、无页面横向溢出；1280 桌面端层级清晰。
- [x] 员工历史聚合金额和批量导出权限不扩大。
- [x] `agents:check`、lint、typecheck、测试、build 和浏览器验证通过。
- [x] 本任务经过独立 QA 复核后提交并推送 `main`。

## Risk and autonomy

- `R3 / L2`：全局用户可见行为和服务端列表规则变化，具备代码回滚；不包含生产数据写入。
- 老板已批准本计划、实施和最终 `main` 推送。
- 若实施需要生产数据、schema、权限或通知行为变化，升级为 `R4` 并停止等待单独批准。

## Work packages

1. 恢复上下文并只读核对当前列表、分页、分类、权限和测试路径。
2. 冻结终态可见性与进行中状态映射，记录上一规则的 Plan Delta。
3. 实施统一服务端过滤、分组分类和 mock/API 契约。
4. 实施桌面/移动端状态筛选与订单卡片层级标签。
5. 运行聚焦测试、完整质量门禁、权限回归和视觉验证。
6. 独立 QA/发布复核、文档记忆同步、提交并推送 `main`。

## Rollback and pause conditions

- 代码回滚为撤销本任务提交，恢复上一版首页归档规则。
- 若非终态订单数量减少、历史搜索失效、租户/角色权限变化或状态映射无法无损表达，暂停并修正后再继续。
- 若远端 `main` 在发布前漂移，先 fetch、复核差异并重新运行受影响门禁，禁止强推。

## Definition of done

- 所有验收标准有自动化或浏览器证据。
- 无生产数据写入；无秘密、客户 PII 或无关改动进入提交。
- 相关文档与任务记忆同步，远端 `main` SHA 验证成功。
