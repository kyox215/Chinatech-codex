# 概览快速接单一致性修复与关联逻辑审计报告

## 已实施

概览页桌面端和移动端的“快速接单”现已复用维修工单列表的同一个新建工单弹窗。普通点击保持在概览；关闭后仍在概览；重新打开使用新的表单会话；创建成功后进入新工单详情。链接仍保留 `/orders/new`，因此修饰键点击、新标签页及无 JavaScript 场景仍可使用独立页面。

为防止两个入口后续再次漂移，弹窗外壳已抽为 `src/features/orders/components/new-order-dialog.tsx`，概览与工单列表共同调用。

## 已确认但本任务未修复的问题

### P1 — 客户管理的“确认尾款”状态与工单付款状态机不一致

客户模块主要按 `balance_amount > 0` 汇总并展示待收款，没有完整复用工单详情对审批、驳回、异常、退款、取消等状态的判断。因此订单即使已经完成，只要旧余额仍为正，客户页仍可能显示“确认尾款”；进入工单后又因报价待审批等条件无法收款。这也会污染客户待收款汇总和筛选结果。

建议建立唯一的跨模块付款资格规则：客户页只能在工单详情状态机返回 `canCollectPayment` 时显示可执行“确认尾款”；其他情况显示准确原因，例如“报价待审批”“付款异常”或“已完成但需数据更正”。

### P2 — 从客户管理进入工单后丢失返回上下文

客户详情、设备和档案中的工单链接直接进入 `/orders/{id}`，而工单详情页内的返回按钮固定回 `/orders`。浏览器返回仍可能有效，但页面内返回会丢失原客户、筛选条件和页码。

建议使用受校验的 `returnTo` 或路由状态，并仅允许站内客户路径，避免开放重定向。

### P1 — 新建工单缺少通用备注输入

表单状态已有 `deviceNotes`、`internalTag` 等字段，但新建工单界面没有对应输入，创建请求也没有完整提交通用备注。现有“随附物品备注”不能替代客户需求、维修注意事项或内部交接备注。

建议先明确两种可见性：客户可见备注（可进入签字/打印材料）与内部备注（仅员工可见），再分别落库并在详情、打印和权限层保持一致。

### P1 — Safari 打印预览右侧裁切

用户证据显示 Safari 系统打印预览右侧区域被裁掉。当前打印布局使用固定毫米宽度及多列 grid/flex；自动化 WebKit 检查只验证 DOM 计算尺寸，实际 PDF 验证仍由 Chromium 生成，因此不能覆盖 Safari 系统打印管线。

建议为打印列增加 `minmax(0, 1fr)` 与 `min-width: 0`，预留安全页边距，并把 macOS Safari 实机打印预览加入发布前人工门禁。
