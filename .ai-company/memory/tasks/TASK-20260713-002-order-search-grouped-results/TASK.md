# Task - 订单搜索反馈、状态分组与日期排序优化

## Owner request

优化订单搜索页面和流程：搜索时明确显示正在加载，完成后清晰展示结果；移动端和桌面端都提供完整反馈。订单列表和详情增加日期，结果先按状态分组，再在组内按日期排序。

## Business result

让前台、老板和员工能确认搜索正在执行，快速判断结果数量，并按业务阶段和订单年龄处理工单，避免旧单沉底或把旧结果误认为新结果。

## Confirmed product contract

- 搜索输入使用 300ms 防抖；Enter 和扫码立即提交。
- 搜索过程中保留上次结果，但必须显示“正在搜索/正在更新结果”，不能把旧结果伪装为最终结果。
- 完成后使用页面内结果摘要和轻量动态反馈，不使用阻断式结果 Dialog。
- 默认分组顺序：处理中、下单、到货、到货已通知、修好、修好已通知；完成和作废仅在授权历史/搜索结果末尾显示。
- 组内按 `created_at` 从早到晚排序；同日期按 `public_no`、`id` 保证稳定。
- `updated_at` 不参与组内主排序，避免备注、金额或非状态编辑导致队列跳动。
- 显示格式使用 Europe/Rome：绝对日期时间 + 相对时间。
- 不新增数据库字段；详情的当前状态时间从既有 `status_changed` 事件派生。

## Scope in

- 搜索 draft/committed 状态、防抖、立即提交、取消过期请求和页面可见反馈。
- 加载、更新、成功、零结果、失败、重试和清除搜索状态。
- 服务端与 mock 统一执行状态分组优先、组内日期其次的稳定排序，且在分页前完成。
- 移动/桌面列表按状态渲染分组标题、组数和订单日期。
- 订单详情强化送修日期和当前状态时间。
- 自动化测试、权限回归、320/390/430/1280/1440 视觉验收和任务文档。

## Scope out

- 生产数据、SeaTable 数据、schema/migration、权限、状态转换或通知发送行为。
- 搜索引擎/全文索引替换、新依赖、其他模块排序或无关订单详情重构。
- 生产部署、远端数据库操作、客户沟通和未经单独批准的 `main` 推送。

## Acceptance criteria

- [x] 输入停顿约 300ms 后查询；Enter/扫码立即查询，过期请求不会覆盖新结果。
- [x] 搜索/更新期间移动和桌面均有可见 spinner、状态文案及 `aria-live` 公告。
- [x] 成功显示查询词、总数、待办数和历史数；零结果与错误有专用状态和操作。
- [x] 结果按固定状态顺序连续分组，组内 `created_at` 最早优先并跨分页稳定。
- [x] 空分组不渲染；分组标题显示本页数和总数。
- [x] 移动卡和桌面行显示送修日期及相对时间；详情顶部显示送修日期和当前状态时间。
- [x] 完成/作废默认仍隐藏，授权历史搜索和角色金额/导出边界不变。
- [x] 320/390/430 无横向溢出或固定头遮挡；1280/1440 分组与日期完整。
- [x] 聚焦测试、`agents:check`、lint、typecheck、完整测试、build 和浏览器验证通过。

## Risk and autonomy

- `R3 / L2`：全局用户可见搜索与服务端排序变化，可通过代码回滚；无生产数据写入。
- 强制停止点：需要 schema、生产操作、权限扩张、通知副作用或外部服务时重新分类并请求批准。
- Agent use：主线程保持单一写入者；真实生成独立只读 QA 与 UX 复核者，两者最终均返回 PASS。

3. 实施服务端、mock 和分页前稳定排序。
4. 实施移动/桌面分组列表、日期与详情元信息。
5. 补齐单元、集成、权限、响应式和浏览器验证。
6. 独立 QA、文档/记忆同步和关闭报告。
