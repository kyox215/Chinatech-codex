# 全站工单入口与订单详情统一报告

## 结论

所有跨模块的普通“新建工单”和“查看工单”入口已经统一进入 `/orders` 工单工作区。工单列表负责解析可分享、可刷新恢复的工作区意图，并打开现有的共享新建工单弹窗或工单详情弹窗。

独立 `/orders/new`、`/orders/{id}` 和 `/orders/{id}/task` 路由没有删除，继续服务深链、移动工单页、任务流以及明确的“在新页打开”场景。

## 统一规则

| 动作 | 标准目标 | 结果 |
|---|---|---|
| 跨模块新建工单 | `/orders?workspace=new-order...` | 工单列表打开共享 `NewOrderDialog` |
| 跨模块查看工单 | `/orders?workspace=order-detail&orderId=...` | 工单列表打开 `OrderDetailScreen surface="dialog"` |
| 工单列表桌面行 | 本页状态 | 继续直接打开详情弹窗 |
| 工单列表移动卡片 | `/orders/{id}?from=orders` | 继续使用移动详情页标准 |
| 工单任务 | `/orders/{id}/task` | 继续进入任务工作流，不改写为普通详情 |
| 在新页打开/独立深链 | `/orders/{id}` 或 `/orders/new` | 保留独立页面降级能力 |

## 已修复入口矩阵

### 新建工单

- 概览“快速接单”：普通点击继续在概览打开同一个共享弹窗；修饰键/新标签页进入可恢复的工单工作区 URL。
- 全局命令面板“新建工单”：进入工单工作区并生成新的接单会话。
- 移动工作台快捷动作：进入工单工作区并生成新的接单会话。
- 客户详情页顶部、空态和操作区：进入共享弹窗并保留 `customerId`。
- 客户设备卡片与设备 Sheet：进入共享弹窗并同时保留 `customerId`、`deviceId`。
- 工单列表“新建工单”：继续使用本页共享弹窗。

### 工单详情

- 概览优先工单“查看工单”。
- 全局命令面板的工单搜索结果。
- 客户详情的最近工单、历史工单、设备维修记录和表格查看按钮。
- 客户设备 Sheet 中的主要工单和历史工单。
- 利润中心的工单明细下钻。
- AI 助手返回的工单卡片。
- 扫码器识别到的普通内部工单链接和 `order:` 编号。

上述入口全部进入 `/orders` 工作区并使用工单模块本身的详情弹窗，不再各自进入不同的桌面详情表面。

## 明确保留的例外

- `/orders/{id}/task`：任务流有独立状态处理职责。
- 客户公开查询解析到员工任务页：属于客户状态处理流程。
- 工单列表移动卡片：遵守 RepairOS 移动详情页标准，保留完整页面。
- 工单列表“在新页打开”：名称明确要求独立页面。
- 返修/原工单关联、任务页内“打开审批处理”：属于工单模块内部深链。
- `/orders/new`、`/orders/{id}`：保留刷新、书签、外部深链和无工作区上下文降级。
- `src/routes/orders.index.tsx`：遗留未被 App Router 引用的路由文件，本任务未扩大为遗留代码清理。

## 生命周期与可恢复性

- 工作区 URL 可刷新恢复对应弹窗。
- 新建工单客户/设备预填会传入共享 `NewOrderScreen`。
- 创建成功后，新建弹窗关闭并在同一工单工作区打开新工单详情。
- 关闭新建或详情弹窗会清理 `workspace`、`orderId`、`source` 和预填意图参数，同时保留工单搜索参数。
- 浏览器验证期间发现首次实现关闭后只隐藏弹窗、URL 未清理；现已改为根据打开→关闭状态转换同步原生 History，并由 E2E 验证通过。
