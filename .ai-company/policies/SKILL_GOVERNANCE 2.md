# SKILL GOVERNANCE — Skills 生命周期制度

## 1. 定义

Skill 是可复用工作流程，包含触发描述、输入、步骤、输出、验证和停止条件。它不等于 Agent，也不自动获得额外工具权限。

## 2. 设计标准

每个 `SKILL.md` 必须：

- 有唯一 `name`。
- 描述明确“何时触发”和“何时不触发”。
- 优先把关键触发词写在 description 前部。
- 只解决一个可命名问题。
- 说明所需输入和缺失输入的处理。
- 产出下游可直接使用的结构化交付物。
- 包含风险、证据和记忆更新要求。
- 不复制整个公司制度。

## 3. 渐进式加载

根 `AGENTS.md` 只保存路由。Skill 被选择后再读取完整流程。若一个 Skill 需要详细参考，放入：

```text
skill-name/
├── SKILL.md
├── references/
├── scripts/
└── assets/
```

避免在 Skill description 中塞入长规则，防止初始 Skill 列表挤占上下文。

## 4. 显式与隐式触发

高风险或关键阶段应显式调用，例如：

```text
运行 $data-migration-review 和 $security-review。
```

低风险常规流程可由 Codex 根据 description 隐式选择。

## 5. 版本与 owner

生产使用的 Skill 应记录：

- owner 部门。
- 版本。
- 最后验证日期。
- 适用技术栈。
- 已知限制。
- 评估任务或测试集。

本包在 `CAPABILITY_REGISTRY.md` 和 Agent 档案中维护这些信息。

## 6. 变更流程

```text
观察到失败/重复工作
→ 创建改进候选
→ 最小修改
→ 在历史任务或沙箱用例评估
→ Reviewer 审查
→ 灰度使用
→ 记录结果
→ 正式采用或回滚
```

禁止因为某次任务输出看起来不错就直接重写核心 Skill。

## 7. 评估指标

- 任务成功率。
- 关键遗漏率。
- 虚假完成声明率。
- 返工率。
- Token 与时间成本。
- 人工升级次数及合理性。
- 记忆更新准确率。
- 对范围外文件的影响。

## 8. 退役

Skill 退役时：

- 标记 superseded。
- 指向替代 Skill。
- 保留历史版本和评估证据。
- 移除重复名称，避免选择器混乱。
