# 维修项目内部成本

## 功能边界

维修项目内部成本是店铺敏感数据，和客户报价分开保存。设置页“默认规则”中的默认成本只会在新订单项目创建时生成快照；修改默认值不会改写已有订单。空白表示未知成本，`0` 表示明确零成本。

本功能不提供利润报表、成本导出、库存/供应商自动关联、历史订单回填或多币种成本。客户消息、打印、普通订单列表、普通订单详情 DTO、实时广播与离线 IndexedDB 均不得包含成本值。

## 权限

- `owner` 固有 `finance:cost_manage`。
- `manager` 默认没有该权限，只能由店主单独授予。
- `technician`、`sales`、`viewer` 不能获得该权限；伪造 grant 也必须被权限矩阵拒绝。
- `finance:profit_read` 可以读取订单内部成本，但不能修改成本或店铺默认成本。
- 成本管理不隐式授予利润或汇总财务权限。

未获授权时，前端不挂载成本组件、不发成本请求，也不显示成本文案。服务端仍在路由、服务层和数据库 RPC 三层独立校验权限与店铺范围。

## 数据与并发

- `store_fault_cost_defaults` 保存当前店铺目录项目的默认成本。
- `repair_order_line_costs` 用 `order_id + line_id` 保存订单项目成本；移除的报价项目只标记 `is_active=false`，不删除历史证据。
- `fault_prices` 只增加非敏感的 `line_id` 和 `catalog_key`；成本值不进入 JSON 报价字段。
- 默认成本保存与订单成本修正使用版本号 CAS。并发版本不一致时必须刷新，不能覆盖他人修改。
- 报价项目新增时快照当时默认成本；后续默认值变化不影响订单历史。

## 发布顺序

功能开关 `REPAIRDESK_ORDER_COSTS_ENABLED` 默认关闭，只有精确等于 `1` 时才投影能力并开放成本 API。生产发布顺序：

1. 对 linked 数据库执行 migration list 与 dry-run，确认只有本功能迁移待应用。
2. 先应用迁移并验证表、约束、触发器、RPC、RLS、ACL 和权限授权；此时旧代码继续正常工作。
3. 再部署新代码并保持开关关闭，避免出现已有 `line_id` 但尚无成本快照行的订单。
4. 设置开关为 `1` 并重新部署。
5. 分别用店主、获授权店长和低权限员工做冒烟测试。

禁止在迁移前部署会写入稳定 `line_id` 的新代码；成本迁移不回填历史订单，因此必须采用 migration-first 顺序。

回滚优先关闭功能开关。迁移为加法式且不回填历史；为保留审计证据，不在紧急回滚中删除成本表或成本记录。
