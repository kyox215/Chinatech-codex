# 复杂任务协作说明

状态：2026-09-15精简版。权威入口：[AGENTS.md](../AGENTS.md)。原声明见 [快照](archive/governance-20260915/complex-requirement.snapshot.md.txt)。

## 流程

1. 从自然语言明确目标、约束、验收、非目标和停止条件。
2. 只有存在独立交付物时才并行调查；按需选择产品、架构、数据、安全、UX或QA视角，不为角色数量启动代理。
3. 主线程记录会影响业务、安全或兼容性的真实分歧；需要时进行一次交叉质疑，避免循环争论。
4. 范围明确后由单一写入者实施；模型按根规则，旧“固定Luna writer”已失效。相关可逆细节由执行者判断，不重复索要批准。
5. 高/关键风险、公共接口、权限/支付/隐私、持久化/迁移/生产变更保留一次独立专项审查与适用正式门禁。
6. 主线程核对目标与证据，按跨会话规则完成最终集成；子代理不得提交、发布、迁移、处理秘密或完成最终集成。

## 边界

- 子代理默认只读；写入需明确互斥路径，不能覆盖别人修改。
- 不递归委派；模型、并发、时间和等待上限只由当前根规则与long-running-task-guard决定。
- 用户明确要求多代理时真实调用工具；不能调用时说明具体原因，不能把角色标签冒充已派出代理。
- 多代理不扩大生产、秘密、客户数据、支付、租户或发布授权。
- 交付实际结果、验证、截图或具体环境阻塞；未验收不能宣布全部完成。
