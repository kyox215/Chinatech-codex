## 已确认的实现基线

- 整机一机一档；客户设备、门店自有单机、商品型号分别维护。新建／复制先明确选新机或翻新机，编号在创建边界按门店日期生成，不能通过普通编辑或修改入库日重排。
- 普通资料、检测和销售操作在所属区域编辑，输入后核对再确认，取消不写历史。输入按数据适配：电池图形及整数百分比、容量预设与自定义、逐块磁盘、目录搜索、颜色宫格、金额欧分、日历日期、整数数量。保持未知与实测零的区别，不猜测实物配置。
- 维修细分选项锚定分类箭头，组装技术在同一非模态小面板切换，不在网格下撑开。配件偏好是客户请求，不能自动成为检测结论或报价授权。
- 维修与整机打印均在预览旁选择意大利语、英语或中文，默认意大利语；系统标题及结构化值使用所选语言，客户自由原文、品牌、型号及标识保留。语言选择不增加到门店设置。
- 门店维修／整机默认商家保修初始为 6／12 个月，可分别设置 1–120 整月。新接机冻结维修政策；新整机草稿继承整机默认，单机仍可选择无额外商家保修；出售时冻结原约定。已售未知资料不能用当前默认补造。
- 接机末步可跳过签字，详情可补签／重新签署。笔迹及采集比例、事实快照、政策、语言、条款版本、时间和操作者绑定保存；历史追加，旧签名只对应原事实。
- 售出、逐笔款项、实际交付、售后维修、实物退回、退款及复检复售是分别核对的事实。客户按归一化号码查看维修与销售记录；售后关联原销售，不把客户送修设备变成可售单机。
- 员工角色与能力、账号与成员状态控制正常读取和保存；成本、毛利及敏感历史仅给 `financial.read` 财务读取权限。原始 fixture／localStorage 不具备正式保密边界。

详细字段、状态及证据分别见[维修与客户闭环](10-work-order-customer-loop.md)、[售卖与员工权限](11-retail-sales-staff-plan.md)、[规格与分类](12-retail-specifications-execution-plan.md)、[输入与就地编辑](13-retail-input-audit-plan.md)、[接机打印与签名](14-repair-intake-print-signature-plan.md)。这些范围不是未来改动的重新授权清单；最新用户要求仍优先。

## 后续修改的完成条件

新增和修改功能遵循根AGENTS的质量与响应速度要求。2026-10-03 用户已要求删除未上线性能分支并恢复正式main，原[性能计划20](20-performance-optimization-plan.md)只作历史参考，不自动合回已放弃实现。沿受影响的读取、提交、关联展示和恢复路径检查数据量、重复工作、加载与交互反馈；必要时固定数据规模和设备进行前后比较。计数/分组/查重/历史不能因分页或缓存失真，权限、幂等、事务、历史和原有图片质量不能为提速降低。

1. 按项目记忆与本矩阵定位受影响的事实、状态、来源和使用方。小改直接执行；多步骤保留简短计划，高影响规则先核对必要反例，不为每轮新增固定报告。
2. 同步适用的输入、领域校验、存储兼容、权限与读取投影，再更新页面、打印及关联记录。未改变的原销售、签名与原条款保持可追溯，不靠改历史让新页面成立。
3. 按影响验证主路径与失败路径：输入／操作 → 核对 → 保存成功 → 共享展示更新 → 刷新恢复 → 关联反向可查；覆盖取消不写、陈旧版本、权限变化、坏存储或容量失败等适用反例。售后跨存储同时检查部分成功后的恢复与重复点击。
4. 代码变更运行适用业务测试及项目 lint、typecheck、build；UI 变更检查受影响页面 1440、1024、390、375 宽度及实际交互。共享源码、环境和风险未变的已有证据可复用，不能拿旧截图替代受影响的新行为。签名硬件、相机、跨设备或实体打印须分别保留真实验证与未验收状态。
5. 修改字段、状态或业务规则时，同步对应业务规格；新增公共 API／变体时更新 [组件复用规范](06-ui-components-and-styles.md)。在 [决策与真实进度](04-decisions-progress.md) 记录实际完成、证据及剩余限制，再在 [项目连续记忆](../PROJECT_MEMORY.md) 保留简短指针。修正过期的当前规则描述；带日期的历史验收保持原事实，并注明后续覆盖入口。

未完成受影响的关联入口、历史保护或必要验证时，明确说明缺口，不能将单页成功称为整体闭环。门店／历史资料、账号、权限及真实交易不得借此声明扩大授权；[跨设备同步研究](15-seatable-realtime-sync-report.md)仍是待正式接入的方案。

## 2026-10-03 账号身份联动

账号主邮箱/手机及Google/Apple关联由Supabase Auth维护，使用[账号绑定规则23](23-account-linking.md)。邮箱双确认成功后，既有auth.users→v2.accounts触发器同步展示邮箱，用户ID、门店成员和权限保持原事实。手机号验证码和OAuth回调必须核对发起身份，不得把验证结果用于另一个已登录用户；多标签切换账号拒绝旧草稿。

itemQuotes／itemQuoteHistory由intake保存，维修项title唯一；历史服务端追加，旧客户端遗漏不清除。新建、供应商快捷表单、详情、客户关联的工单及三语打印读同源报价；不加入旧接机签名对象。save-item事务联动采购、workflow要求、intake报价与幂等回执；repair.quote只更正报价，不碰采购与维修阶段；procurement.reconfirm原子核对完整项目引用，不能覆盖订单与到货事实。成本保持procurement.unitCostCents，读／写权限在服务端执行，前端仅按相同能力显示输入或只读事实。需求变化后的旧记录必须明确核对，未选择或未到货的其他项目继续影响到齐判定；到齐仍不自动开修。详见计划22最新段。
