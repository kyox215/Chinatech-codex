- 项目、配件要求、客户报价、供应商选择同一行/同一张手机项目卡；报价之后紧跟供应商。桌面宽表只在自身面板滚动；手机不照搬宽表。
- 复用现有PageTitle、Brand、InputControl、SearchCombobox、SelectControl、LanguageProvider、OperationFeedbackProvider/ContentProgress及button/panel/status-pill语义类。预览仅添加领域布局，不修改公共控件或主题。

## 1. 一项维修，一处看清

每项依次展示：**项目＋配件要求 → 客户报价 → 本项供应商 → 采购进度**。

- 屏幕：组装/Incell；报价€90；选择本项供应商。
- 电池：组装/扩容与诊断；报价€60；独立供应商。
- 尾插：组装；报价€40；独立供应商。
- 报价合计仅显示一次。未报价为未知，不能算€0；显式€0保留。客户报价与供应商进价分开，成本仍受权限投影保护。
- 点击金额或供应商在项目内编辑/弹层核对，成功后同步主行与供应商分组，取消和失败保留原事实。已下单或同项多采购不能覆盖供应商/进价，可独立更正报价；多采购按原记录展开。
- “保存报价/确认录入”不等于客户同意维修。现有报价沟通没有accepted/declined授权合同，不新增假“客户已同意”状态。
- 原报价历史从itemQuoteHistory读取；供应商关联用requirementId+revision，不靠屏幕/电池等显示名猜配对；自定义和无配件服务项目沿真实需求投影。

## 2. 手机分组与页头

页头同一行：菜单44px、返回44px、工单详情、打印44px；桌面打印带文字，手机图标保留可访问名。设备摘要压缩，型号/当前阶段直接可见，客户及完整识别信息可展开。

| 分组 | 内容 |
| --- | --- |
| 维修（默认） | 故障报告、逐项目要求/报价/供应商、唯一合计、报价与签署提醒；联系入口可达。 |
| 供应商 | 同一批项目的采购视图，供应商、规格、数量、进价权限、下单与到货、更正/多记录；不会再复制一份独立报价数据。 |
| 照片 | 接机照片独立收纳，正面/背面/其他、数量、放大、待保存登记；切分组不丢草稿。 |
| 历史 | 维修/报价/采购/联系/签名来源明确的时间线，可筛选；已有历史原话不改写，不把所有更新时间当操作事实。 |

分组是页面局部导航。切换同步即时反馈，保留编辑/滚动；有真实请求才启用B细线和控件单圈。桌面同样可用分组，维修页保留紧凑侧栏概况；手机把概况/客户收为可展开区域，避免连续堆卡。

## 3. 供应商与采购车移除

新流程：**项目要求 → 选已登记供应商/填进价 → 保存为待采购 → 确认已实际向供应商下单 → 登记实际下单 → 分次到货/更正**。系统没有自动向供应商下单能力，保存选择不能显示“已下单”。

采购车不是独立basket表，而是ProcurementRecord.events里的cart_added/cart_removed。实施时删除按钮、购物车弹窗/筛选/图标、自动加车与批量从cart下单路径；新命令不再生成cart事件。旧cart/draft统一按未下单展示，保留历史解析与旧事件原文；不删除已下单、到货、更正或供应商记录，不把旧cart升级为ordered。

保留：逐项目直接下单、采购详情、分次到货、更正、批量到货、备选/多采购、版本核对及双向工单关联。现有单条ordered本就允许draft，不需要新建购物篮。

联动入口：repair-list、procurement-list、supplier-batch-dialog的cart分支（arrival保留）、procurement-preparation、repair-items-form、repair-part-form、procurement-detail/create、repair-procurement-shortcut；lib/procurement、repair-item-editor、procurement-batch、backend/commands/input/contracts、provider及storage兼容；三语词条、采购教程脚本与三语视频/封面/字幕一起更新。不能只删维修列表按钮。

## 4. 联系与跟进只选择

报价沟通：**已沟通报价 / 未接通 / 等待客户回复 → 记录结果**。不再要求手写说明；选中和提交分开，降低误点即写入。旧备注原文在历史里保留，新记录可为空备注，系统仍记录实际操作者/时间/结果。

- 必须同步RepairContactControl按钮门控、applyWorkflowCommand及validateWorkflowExtensions空备注校验，保存/刷新解析一致。不能用伪造备注绕过校验。
- 沟通不等于同意维修/付款/交机，也不自动变阶段。到货和取机通知仍按配件/设备保管/readyCycle分别门控。
- “久等未回复/结束跟进”可选择操作；“设备已交还且未结清”涉及实际事实，仍需明确核对交还与未结清，不默认勾选。更正/恢复维修等必要原因不随本轮一并取消。
- 未选择不能记录；等待仅锁本次提交，失败保留选择；409保留核对，未知结果沿原requestId恢复，不制造第二次联系记录。

## 5. 照片独立登记

第一阶段复用现有接机照片front/back/other，集中在照片分组，按数量/缩略图/放大收纳；不把真实照片拷入设计稿。预览使用明确标记的示意图与本地选图草稿。

正式追加/更正登记应核对现有上传命令、门店/工单权限、照片ID/版本、原文件引用与失败恢复，成功才更新计数，取消/失败保留草稿；旧照片未知时间/操作者不能补造。照片当前不属于接机签名快照，不因挪位置改变签名范围。维修过程/交付阶段照片若后续新增，应独立确认字段合同，第一期不伪造这些现有分类。

## 6. 状态与闭环

- 读取/刷新：同范围保留内容；无旧内容时真实标题框架+局部短等待；失败重试，不用整页灰骨架。
- 保存：原按钮单圈+内容顶部2px线；失败保留当前输入/选择，成功才关闭；冲突先读新版本再核对，未知沿原ID查询/重试。
- 分组/设备变化：同工单草稿保留，身份/门店/权限变化立即隔离私有资料，迟到响应不能回填。
- 签署/打印：项目要求改变沿原签名失配合同，旧签名和报价历史保留；进价/供应商和日常沟通不塞入原签署/打印对象。新建、列表、详情、客户设备、打印同源。
- 三语、键盘Tab/方向键/Enter/Escape、44px/16px、减少动画与正式CSS顺序都按现行规则验收。预览验证不能冒称后端或生产写入通过。

合并展示还有三条数据边界：

1. 供应商按requirementId/revision关联；报价沿现有itemQuotes的item键。用视图模型明确quoteItemKey映射，不添加未经设计的数据库外键。无法可靠配对的旧报价/旧采购保留“待核对”，不靠显示名猜合并或丢掉。
