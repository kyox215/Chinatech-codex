## 实现范围

新增 [release 工具](../desktop/office-assistant/release/README.md)，独立于正在修改的 0.2.2 候选。没有改 build.py、应用界面、联网准入、网站开关、最低版本或 Office runner，没有将该候选直接接入发布。

- prepare.py 冻结 ARM64/x64 两个正式包：核 SHA、大小、PE 架构、未签名状态、新版本递增，以及原 build.py 的正式构建 manifest。输入声明和复制结果全部匹配后，最后才发布 input-manifest.json。开发包、错误元数据、链接路径、已有输出或中途变化均拒绝。旧版仅可 inspection-only，不能借此重签覆盖现有发布资产。
- Sign-OfficeRelease.ps1 支持 Windows My 证书库/硬件私钥及 Microsoft Artifact Signing 两种配置；示例字段为空，无法冒充实名配置。不接收 PFX 密码、不导入证书或根证书、不自动登录 Azure。云模式固定检查 tenant/subscription，限定 PublicTrust/profile EKU，排除其他默认凭据来源。
- 签名固定 SHA256 文件摘要和 RFC3161 时间戳。Test-OfficeAuthenticode.ps1 要求嵌入签名、完整预期发布者、代码签名 EKU、可信时间戳、Windows 信任判定及微软 SignTool `/pa /all /v /tw` 的严格 exit0。保守拒绝 catalog、nested、多主签名；传统证书额外检查 AuthRoot 来源，这一保守条件的公共 CA 覆盖尚未实测。
- OfficePePayload.ps1 在签前/签后比较全部原文件内容，包括 .NET single-file bundle。只屏蔽 checksum 4 字节与 Security Directory 8 字节，并核证书末尾追加位置、对齐、零 padding、单 WinCertificate 和无尾随内容。程序内容变化报 PAYLOAD_CHANGED，不能产出成功清单；此检查不代替真实签名验证。
- 两个架构全部通过才原子写入 signature-verified.json，记录签后最终 SHA、原始内容摘要、构建来源及信任事实。记录仍为 releaseReady=false、requiresAcceptance=true，不是发布授权。后续下载、上传与放行必须使用签后的 SHA。

独立源码复核发现并修复了两项问题：签名期间副本被换成同版本其他内容；完整输出已提交后的临时清理失败被误报为打包失败。前者增加全原始内容绑定，后者保留成功结果并报告固定清理告警，前置失败不被清理错误覆盖。最后独立复核未发现新的实质绕过；这仍是源码判断。

## 错误后的处理

| 错误码 | 处理 |
| --- | --- |
| SIGNATURE_MISSING / SIGNATURE_INVALID | 停止发布；从冻结的正式输入重新签名并校验，不绕过告警 |
| SIGNER_MISMATCH | 核实名发布者与证书完整 Subject/绑定配置，不能改预期身份去接受无关文件 |
| PAYLOAD_CHANGED / INPUT_CHANGED | 丢弃本轮副本，核构建和签名机，从原冻结输入重新准备，不改 SHA 清单掩盖变化 |
| INSPECTION_ONLY / VERSION_NOT_INCREMENTED | 使用完成验收的新版本，不能重签覆盖已发布0.2.1 |
| FORMAL_BUILD_REQUIRED / BUILD_METADATA_INVALID | 提供对应双架构原始正式构建 manifest，并核版本、生产地址、runner与文件摘要 |
| CERTIFICATE_UNAVAILABLE / PUBLIC_TRUST_UNCONFIRMED | 检查证书/硬件私钥是否可用及公共信任；没有可信证书则办理实名证书或服务 |
| SIGNTOOL_UNAVAILABLE / SIGNTOOL_UNTRUSTED | 在受控签名机使用微软 SDK 官方签名工具，不替换成来源未知工具 |
| AZURE_CONTEXT_MISMATCH | 明确核对本项目 tenant/subscription/账号/profile 与权限，再由负责人切换正确身份 |

## 下一步所需条件

两条路线已经准备好配置模板：现有公开可信的 Windows 代码签名证书，或已完成组织身份验证的 Microsoft Artifact Signing PublicTrust。意大利组织处于当前支持的 EU 范围；个人开发者目前须位于美国或加拿大，不能假定意大利个人身份可开通。[微软准备条件](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart)。账号还需正确的签名角色及同一目标的配置，不能借用其他项目身份。

取得条件后，在允许脚本执行的受控 Windows 签名机/CI 上，先完成正常脚本链和双架构真实签名/时间戳验证，再使用下一个已完成应用验收的新版本。当前另一任务0.2.2尚未完成，不能把它当作签名正式输入。随后保持防护开启，重新经 Chrome/Edge/Firefox 下载最终文件，核 SHA/MOTW、实名发布者、实际启动/联网及相关业务，再发布并更新最低版本。

签名改善发布者身份和信誉基础，但不保证新文件立即没有 SmartScreen 提示，也不保证所有杀毒无告警。[微软 SmartScreen 说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。真实第三方杀毒问题仍需对应厂商的文件核查/申诉，未提交不能声称已消除误报。签名参数与严格验证参考 [SignTool 官方文档](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool)。
