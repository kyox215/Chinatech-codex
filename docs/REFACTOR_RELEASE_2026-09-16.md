# RepairDesk 核心流程与录单体验更新

本记录描述2026-09-16冻结并验收的发布内容；正式上线状态以对应提交的Vercel部署记录为准。

## 用户可见变化

- 工单列表首批100条，滚动到底继续加载100条；手机支持下拉刷新，加载失败可以重试。
- 新建工单提交时，高亮整行遗漏项并定位第一处错误；品牌和型号支持名称、前缀和硬件代码联想。
- 订单联想补充424条已核实欧洲硬件代码的设备身份，保留共享代码的多个候选。完整资料见[欧洲设备表](EU_DEVICE_MODEL_CATALOG_2026-09-16.md)。
- 精简导航和列表说明，品牌Logo返回首页；队列窗口限宽，显示当前与下一阶段的进度。
- 客户与设备编辑使用版本校验；标签替换、设备删除和普通通知记录使用事务，冲突时保留草稿。
- 产品AI助手、相关接口和定时任务已移除。本地OCR、条码与IMEI校验继续保留；历史AI账本和数据库迁移保留以供审计，不再作为启用入口。

## 数据与兼容

此次数据库发布由六份现有前向迁移组成，合并为一个事务，避免中间触发器影响旧导入流程：

1. `20260915232139_customer_write_consistency.sql`
2. `20260915233656_customer_activity_revision.sql`
3. `20260915234637_customer_device_delete_atomic.sql`
4. `20260915235504_customer_cas_version_payloads.sql`
5. `20260916044416_order_notification_atomic.sql`
6. `20260916050954_order_notification_recipient_history.sql`

迁移不删除业务行或历史账本。部署台账应记录工具实际分配的版本与以上源文件的对应关系；不能直接把不同版本号假定为同一条迁移，也不能未经历史映射核对直接执行全量`db push`。

应用回退候选须保留已经验收的客户版本校验、通知事务和AI移除。更早的生产版本仅作为历史参照，不能直接当作保留这些保护的回退点。

## 验证范围

本轮验收覆盖电脑、iPad和手机的列表加载/重试、筛选、必填定位、型号联想及新建工单。最终全量521个测试文件、4818项测试通过，类型检查、lint与生产构建通过。真实本地Auth的老板/前台双账号验证通过：屏蔽广播后约30秒自动收敛，断网恢复无需手动刷新，跨门店详情拒绝读取。此验证开启已有revision开关，不代表其他环境开关值。

模拟数据的浏览器测试与真实本地Auth/数据库事务测试分别记录；它们不代表已完成所有角色的全项目业务验收，也不等于外部消息真实送达。

详细审计报告、测试原始证据和私有测试环境信息由本地任务保留，不随公开源码发布。完整重建能力、其余重构待办和旧销售流程的后续取舍继续跟踪。
