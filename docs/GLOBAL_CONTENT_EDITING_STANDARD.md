# Global content editing standard

Status: **active — Owner selected A, 2026-09-06**. This is the shared interaction authority for the bounded global compact-edit rollout. Historical M16 and inventory release records remain preserved; this document grants no data, permission or production authority.

## Interaction contract

- Tap the visible content or current value to edit. Keep the underlying page geometry and scroll position stable. Give empty values a clear accessible entry.
- Below 1024px use a compact bottom editor. At desktop widths preserve the existing Dialog, anchored Popover or independent workspace. `DialogContent` / `SheetContent` opt in with `mobileEditor`; defaults, capture, filter, print and consequential dialogs remain separate.
- Presentation changes through CSS do not remount an open editor on resize. Draft state belongs to one opening and entity/store, not each query refresh.
- Existing single-value mutations (assignee, supplier) close only after success. Pending prevents duplicate choice; failure retains the open selection surface. Existing draft-only choices remain draft-only.
- Related fields and finance retain explicit Save/Cancel. Escape, X and backdrop pass through the pending/dirty guard. Discard confirmation is an inline step within the same modal, defaults to Continue editing and restores focus. Never convert every field to autosave.
- Finance and device-unlock sessions freeze `updated_at` at opening and checks the existing conflict contract before save. Unsaved quotes cannot feed workflow, payment or WhatsApp actions. Preserve capability checks, version handoff, finance redaction and voided-state rules.
- Real inputs are at least16px on compact screens. Primary save/cancel actions remain at least44px. Instruction14 makes the dense repair-category variant **four columns × three rows, fixed36px single-line cells and4px row gaps**. The left two-thirds select (`aria-pressed`); the right third reveals the full label/options (`aria-expanded`/`aria-controls`). This does not weaken inventory selector or capture targets.
- Use short zh/it/en labels with full accessible names. Tabs are equal width in the compact order header, with Details / Device photos / History, keyboard navigation and per-group scroll memory.
- Photos follow the existing **append-only** attachment API. A tile captures an additional image; separate numbered view controls expose every grouped image. Do not imply replacement or deletion. Upload failure retains the current image in memory until retry or cancel.

## Order detail A layout (2026-09-06)

The compact order overview groups customer and device summaries in one card, keeps fault/diagnosis in its own compact card, places assignee/supplier side by side, and combines quotation rows with a three-column total/deposit/balance summary. Normal custody is a small row within the device group; exceptional custody, cancelled return and existing notices retain their full semantics. Phone, kiosk, scan and unlock controls remain separate interactive targets beside the content trigger. Compact header tabs use an equal-width neutral segmented surface; desktop keeps its independent workspace.

At 390×844, the ordinary local fixture with two quote rows must show the full amount summary above the fixed dock. At 320×568 and with long text, content remains reachable by normal page scrolling. No fixed content height or clipping is used to meet the compact target. This layout keeps the existing editor sessions, permissions, finance redaction, failed drafts, version/concurrency checks, payloads and append-only photos. Evidence belongs to TASK-20260906-003.

## Compact status actions (2026-09-06)

Inside an existing status strip, custody receive/deliver, unknown backfill, cancelled return and terminal correction entry actions use `Button variant="ghost"` with the opt-in `componentAction.status` family. Place state at the start and the wrapping action group at the end. Entry actions have no permanent shadow or raised border; retain visible hover, pressed, keyboard focus and disabled states. Mobile targets are at least 36 px tall (ordinary embedded row approximately 40 px); desktop uses an independent 28 px minimum. Long labels wrap naturally, including at 320 px, without fixed heights or clipping. Warning/correction entries retain warning text and contextual explanation; compact terminal menus keep destructive items distinct.

This presentation contract does not change the confirmation Sheet/Dialog, final confirmation button hierarchy, permissions, pending guard, reason validation, version, payload or custody transitions. Dedicated terminal workflow banners and final confirmation footers retain their stronger hierarchy. Read-only custody badges and next-action guidance remain non-interactive. Finite audit and synthetic screenshots belong to TASK-20260906-004.

## On-demand numeric editing (2026-09-06, A13)

`DialogContent` / `SheetContent` opt in with `mobileEditor` or `initialFocus="container"`: below 1024px opening focuses the non-input content. Callers keep their focus callbacks, dirty/pending guard and close restoration; explicit input autofocus must remain desktop-only. Search/login/capture defaults do not inherit this opt-in.

Use `VirtualKeyboardDock` for money, phone and numeric consumers. In an opted-in modal the dock mounts directly into that modal's bottom host and remains reachable by its normal scroll; ordinary pages keep the viewport dock. Done updates the draft only. First Escape closes the keypad, second Escape reaches the editor guard; Done/Escape restore the trigger, while clicking another field keeps that field focused. The active numeric trigger stays lightly emphasized. Do not create another keypad style or a body portal outside an editor's focus scope.

`MoneyKeypadInput` retains two-decimal drafts and resolves desktop native behavior through the existing user preference. `PhoneKeypadInput` is a controlled business editor: it preserves legacy raw formatting when requested, retains labels/error associations/autocomplete/length limits, and exposes combobox semantics only for a real candidate list. It does not expose native `name`/`required` form props; use the validated native-control adapter for named form controls. `NumericKeypadInput` serves explicitly audited integer/decimal fields; it keeps a real non-readonly native control for name/defaultValue/FormData/required/min/max/step, routes invalid focus to its visible trigger, and supports ten decimal exchange rates, expanding scientific numeric values into ordinary decimal drafts before reopening. All three keypad editors check the source control, including inherited disabled fieldsets and readonly changes, before opening or writing; locking a pending editor closes its keypad. Numeric physical keys forward a cancellable event through the real input and start from its latest value. Mixed IMEI/SN fields and name-capable customer search remain textual; do not infer numeric-only semantics from a field name.

Quote rows and the total/deposit/balance strip reuse `OrderWorkspaceQuoteRow` and `OrderWorkspaceMoneyStrip` with `appearance="quote-editor"`. Computation remains with each caller. Missing quote amounts are visibly unfilled, with a field hint and actionable localized validation; explicit zero remains distinct. Category arrows show inspection options directly for categories without repair specifications; specification categories retain the repair/inspection switch. Historical quote names, including CONTROLLARE, and line IDs/prices/notes are never deduplicated by presentation code.

Supplier management uses the existing settings page in a new tab, only when the ready current user/store/membership is owner and the existing capability allows it. The originating same-store options refresh once on a management return, after a forced existing bootstrap refresh proves the same user/store/membership/role and authority fingerprint; identity/role/store/readiness changes cancel that return session. Identical name/short_name is shown once; supplier records remain separate.

A13 core evidence covers 320×568, 390, 768, 1024 and 1440 synthetic browser flows, keyboard scope and native validity tests. Physical iOS keyboard behavior is not claimed. Finite adoption covers inventory product/intake/legacy form quantities, battery health, costs, sale/payment values and warranties; both active buyback workspaces; procurement quantities/costs, warranty rules, invite/backfill counts and currency rates; and supplier/store/account/kiosk contact numbers. Inventory selectors keep listbox-first focus and explicit search requests. Six-digit security confirmation and one-time-code fields, login/password and text search remain specialized native flows. The task manifest records the corresponding inventory six-width evidence; this standard is not blanket permission to alter persistence, tenant access or unrelated dialogs.


## Compact aligned editors (2026-09-06, A14)

Quote editors use a local 36px first row for name, amount and draft removal. Specification and amount errors occupy the shared secondary row; they never move the first-row baseline. Real mobile text inputs remain 16px, Add custom is 36px, and Save/Cancel stay 44px. The three amount tiles share label/value tracks; deposit uses a fine underline and visible focus instead of a nested card. This opt-in does not change default controls or money drafts.

`editorLayout` explicitly opts DialogContent/SheetContent into a fixed header and footer with one shrinking body scroller (`DialogBody` or `componentOverlay.editorScroll`). The close target is 44px on mobile and stays outside the body scroller. Editor footers use two equal mobile columns, desktop intrinsic actions, and bottom safe area. Confirmation remains a direct child of the modal so `editorConfirmationClass` stays effective; the keypad host stays a direct sibling and first Escape still dismisses the keypad. Short-height editors clip the outer surface against programmatic scrolling, keep the host/footer in normal layout, and bound the internally scrollable keypad to leave room for the header and actions. Finance retains a disabled fieldset while a child grid owns body/footer sizing. Ordinary dialogs and capture shells retain their defaults.

Order identity editing reuses `DenseOptionMenu`, `ImeiScannerField`, and `AccessoryNotesPicker`: brand/model, identifier/capture, accessories, then device notes. Disabled and current permission/pending guards cover native controls and delayed portal/capture callbacks. Automatic IMEI recognition remains checksum-only and manual IMEI/SN text remains supported.

The former fault editor now has one Notes textbox backed only by `issue_description`. It preserves the opening version, dirty/pending guards, conflict reload and failed draft. It never writes or clears `diagnosis_result`; existing diagnosis remains visible read-only in the detail summary. New-order empty descriptions and existing update validation remain unchanged; do not invent placeholder content or copy repair references into notes.

Customer lookup remains phone-first and uses `useCustomerIdentityCandidates`/the shared result panel: 180ms debounce, store-scoped key, current-intent filtering and exact/alternate phone matches. Show phone before name; omit a redundant numeric name only in presentation. New-order selection is unchanged. Detail matches are read-only, mark the current customer and warn on another exact phone; never write another candidate into the current customer's profile. Customer relinking is an optional separate follow-up, not part of this batch.

Finite source adoption: order identity/finance/unlock and notes; customer profile/tags/device/followup; settings supplier/member/store rename. Shared defaults, other dialogs, inventory catalog semantics and backend APIs are unchanged. A14 evidence records the actual synthetic browser and test coverage; source adoption is not a claim that every consumer has browser coverage.


## A14 Owner-approved dense editor refinement (2026-09-06)

The order device/customer, notes and quote editors now opt into `denseEditorSurface` / `denseEditorHeader` / `denseEditorBody` / `denseEditorFooter`; ordinary dialogs retain their defaults. Header is 52px, body rhythm 8–10px, close and primary actions 44px, and mobile editable text 16px. Short labels sit beside their controls; the enclosing `denseInlineField` owns a visible focus-within ring. Header/footer stay outside the body scroller and the existing keypad host/dismissal owner is preserved.

Instruction15 replaces inline quote expansion with an explicit popup. Names/specifications remain single-line at a fixed row height; click or keyboard activation opens the shared quote Dialog. Catalog names and specifications are read-only; custom names that were editable keep a local popup draft. Cancel changes nothing, while Save/Enter only updates the parent quote draft and never submits the outer form. Open focuses the popup container on both mobile and desktop; Escape closes only the inner popup and returns focus without reopening. Body scrolling and separate 44px footer actions keep short screens usable. Money columns, atomic digits, 16px mobile editing, category 4×3/36px/4px density and the original 2:1 selection split remain unchanged.

Device accessories offer four quick choices through the existing selection/none/custom model; the full option menu and existing non-quick values remain visible and reachable, with current disabled guards. Device notes remain last. The single repair-notes input is 104px with a character count, full accessible label/help and existing validation. Customer phone/name fields are compact rows; shared result cards remain phone-first, current-customer status stays visible, and the full detail-only matching explanation is available through an inline disclosure. No customer reassignment or data contract changes are implied.

Evidence for this candidate is under `artifacts/a14/dense-release/`: real application screenshots use only the local synthetic fixture. Coverage includes mobile 320/390/430, tablet 768, desktop 1024/1440 new-order sharing, 320×350 modal/keyboard reachability, focus, retained drafts and failed/pending notes save. Exact executed totals and limitations are in the candidate result receipt.
