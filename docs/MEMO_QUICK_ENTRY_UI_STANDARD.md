# 备忘录快速写入 UI 设计规范（方案 A）

状态：2026-09-26 极简列表与细进度条已批准；第 12 节为当前视觉基准，旧方案 A 的专用灰底/黑色控件仅作历史记录。

适用范围：`/memos` 新建、编辑及清单展开（手机、iPad、桌面）

视觉沿用老板选定的“方案 A · 紧凑快速写入弹层”；2026-09-26 已批准的子清单扩展以下文第 10 节为准。

## 1. 设计目标

用户打开弹层后，第一眼只看到“类型 + 一行快速输入 + 添加详情 + 提交”。普通待办可以在一次输入和一次 Enter 内完成；日期、负责人和正文按需展开，不在初始画面制造负担。

本规范是实现合同，不是风格建议。除响应式落位外，不得擅自增加卡片、渐变、蓝色强调、字段标题、说明框或二次容器。

## 2. 结构与顺序

1. 标题区：`新建备忘`、`快速写下，详情稍后补充`、右上角关闭按钮。
2. 类型区：`待办`、`记录`。默认选中待办。
3. 快速输入：单行白色输入区，文案 `写下要做的事或记录…`。
4. 详情入口：`＋ 添加详情`；展开后原位显示正文、到期时间和负责人。
5. 底部区：左侧 `本店成员可见`，右侧 `添加待办` 或 `保存记录`。

禁止在初始状态加入“标题”标签、字数提示、必填提示、隐私说明框或额外提交栏。校验信息仅在错误或接近上限时出现。

## 4. 字体与层级

- 标题：`14px / 20px`，中等字重；不使用超大标题。
- 描述、店铺可见性：`12px / 16px`，弱化前景色。
- 类型、输入、详情和提交：`14px`；移动端真实输入保持 `16px`，防止浏览器自动缩放。
- 选中态只通过中性深色填充、文字反色和 `aria-pressed` 表达；不使用品牌蓝色。

## 5. 状态规则

- 默认：待办选中、详情折叠、快速输入自动获得焦点。
- 键盘：标题输入按 Enter 提交；详情正文使用 Ctrl/Cmd+Enter 提交；Esc 关闭遵守未保存拦截。
- 空标题：主按钮禁用；输入过空格或临界字数时显示最小校验信息。
- 忙碌：控件禁用，按钮文案改为 `保存中…`。
- 详情展开：在当前弹层内展开，不打开第二层弹窗。
- 编辑、冲突、只读：保留既有业务信息和操作，不得为追求新建态视觉而删除。
- 焦点：使用低对比中性焦点环；键盘可见但不能出现强烈品牌蓝边。

## 6. 响应式与可访问性

- `390px`、`430px` 不得出现横向滚动，键盘打开后主体仍可滚动，底部安全区不得遮住主按钮。
- 所有移动端点击目标至少 `44×44px`；关闭、类型、详情与提交均符合。
- 标题与描述保持 Dialog/Sheet 语义；类型按钮提供 `aria-pressed`；错误使用 `aria-invalid` 和关联说明。
- 颜色不是唯一状态信号，选中态同时具有按压状态，禁用态同时禁止交互。

## 7. 禁止偏差

- 禁止把弹层改回纯白大表单。
- 禁止蓝色大面积选中条、渐变 CTA 或发光阴影。
- 禁止搜索框式框中框、字段外再套装饰容器。
- 禁止初始展示正文、日期和负责人完整表单。
- 禁止在弹层底部加入“上一页 / 下一页”或分页元素。
- 禁止新增与当前快速写入无关的标签、统计、分组或解释文本。

## 8. 实现与验收映射

- 颜色 Token：`src/styles.css` 的 `--memo-quick-entry-*`。
- 组件声明：`src/lib/component-patterns.ts` 的 `memoQuickEntry`。
- 实现：`src/features/memos/forms/memo-editor.tsx` 与 `memo-editor-overlay.tsx`。
- 验收：桌面和移动端真实 `/memos` 新建流程截图；组件测试；`lint`、`typecheck`、`test`、`build`。

视觉验收应并排对照选定截图，重点核对容器灰度、576px 宽度、16px 圆角/内边距、标题区下距、按钮高度、输入白度、底部分隔线与弥散阴影。

## 9. 列表搜索与筛选规范

`/memos` 的列表入口使用与方案 A 相同的克制、快速操作原则：

- 搜索与筛选保持同一行。搜索只有一个可见输入边界；不得在有边框的工具卡内再套有边框搜索框。
- 手机端搜索使用浮动页头中的内嵌浅色输入面，右侧为 `44×44px` 的滑杆筛选按钮；桌面端使用单层搜索框、文字筛选按钮和新建按钮。
- 默认 `当前记录 + 全部类型 + 全部负责人` 时不显示筛选摘要或数量。只有非默认条件激活后，按钮才显示数量，列表上方才显示精简摘要和清除入口。
- 手机筛选为底部 Sheet，桌面为最大 `512px` 的紧凑 Dialog。查看范围和类型使用可换行胶囊按钮，并同时提供 `aria-pressed`；负责人使用原生可访问选择框。
- 筛选弹层内的选择先保存在草稿，点击 `查看结果` 后才应用；关闭弹层不改变当前结果。`清除条件` 先恢复默认草稿，再由用户确认应用。
- 列表不得出现可见的“上一页 / 下一页”或页码。需要续载时只显示居中的 `加载更多`，新数据追加在现有记录之后；加载中禁用按钮并显示 `加载中…`。
- 搜索文字和激活条件可以按需显示摘要，但不得重新引入常驻的“待处理 / 我的 / 超期 / 已完成 / 已归档”状态导航条。

验收覆盖桌面、390px 和 430px：搜索输入不横向溢出；筛选按钮不挤压输入；Sheet 主操作不被安全区遮挡；胶囊可换行；列表续载后旧记录仍保留。


## 10. 子清单扩展（2026-09-26）

本节是老板批准的新行为，取代此前“初始只能显示一行输入”的限制；继续复用原有颜色和组件。

- 待办可添加型号子项，每项自由文字与完成状态，数量可写作“iPhone 17 Pro 透明壳 ×3”。普通记录不提供清单。
- 编辑顺序为标题、子清单、可折叠补充信息（正文、到期时间、负责人）。增删改文字按保存统一提交；退出保留未保存拦截。
- 支持逐行添加、多行粘贴；空行忽略，重复型号不擅自合并。超过100项或单项200字显示错误，不静默截断。
- 首页默认收起，显示“已完成 X/Y”。展开时按需读取详情；每次勾选立即保存，不需要打开编辑页。保存中禁止该条重复写入，失败不显示假成功。
- 有清单时不提供整条一键完成；全部子项完成自动完成整条，取消勾选或新增未完成项自动重开。删除最后一项后恢复普通待办，保留删除前整条状态。
- 完成项可折叠，搜索命中的完成项保持可查看。搜索覆盖标题、正文和子项型号，仍保留现有筛选和分页。
- 标题栏和保存区位于正文滚动容器外，底部适配安全区，软键盘出现后正文仍可滚动。手机输入16px、主要触控目标至少44px。
- 无负责人、无到期时间不在列表重复显示占位；优先展示标题、清单进度及实际日期。
- 验收包含手机WebKit、iPad横竖屏、桌面、短高度与zh/en/it；输入、保存、刷新、冲突和错误重试必须实际操作，截图不能替代行为证据。


## 11. 统一网站设计风格（2026-09-26）

老板明确要求与网站其他页面一致，本节取代第 3、4、5、7、8 节中与公共视觉样式冲突的要求。

- 复用 `componentOverlay` / `componentForm`、公共 Button/Input/Checkbox 及 `repairOs`；备忘录不再使用 `memoQuickEntry` 专属灰底和黑色 CTA。
- 编辑器使用公共卡片底色、边框、字号、焦点及主按钮；header、可滚动 body、footer 分离，手机底部 Sheet 与桌面 Dialog 保持同一业务会话。
- 列表采用公共业务卡和紧凑工具条，日期和总体进度退为辅助信息；每条清单的 X/Y 和展开即勾即存保留。
- 视觉调整不改变保存、未保存退出拦截、权限、版本冲突、门店隔离及审计。
- 保留第 10 节的清单行为，三端和中英意完整操作为验收要求。


## 12. 极简列表与细进度条（2026-09-26）

按用户确认的 C 结构 + B 进度条，只调整备忘录视觉，不改变 API、权限或保存策略。

- 列表使用连续白色工作面，以留白与细分隔线区分条目；移除每项独立边框和阴影。标题 18px、清单正文 16px、辅助信息 12px，长文字自然换行。
- 每个有清单的待办显示 4px 真实进度条及完成数量；数值来自已有清单统计。无清单时不渲染，页头只保留日期与记录数量，不与子项进度混淆。
- 备忘录专用圆形完成控件复用共享 Checkbox 的语义、键盘和禁用行为，控件实际尺寸 44px，视觉圆环 22px；未完成为中性细环，完成为品牌蓝底白勾。全站 Checkbox 不变。
- 标题仍打开编辑器；独立箭头展开清单；圆形控件只改变对应事项完成状态。已完成折叠、搜索匹配展开、只读、离线、忙碌与错误重试保持原规则。
- 编辑清单使用轻分隔输入行和始终可达的删除按钮；标题与新增项使用浅色输入底。保存区固定，长内容仅正文滚动，输入框保留可见焦点。
- 勾选颜色与箭头使用短过渡，进度宽度使用 200ms 过渡；减少动态效果时取消相关过渡。继续沿用共享颜色 tokens 和既有危险状态提示。
- 验收：中/意/英代表视口、手机短屏、iPad 旋转、键盘 Space、44px 目标、长型号、粘贴、保存/重开/刷新、减少动态效果与无横向溢出。
