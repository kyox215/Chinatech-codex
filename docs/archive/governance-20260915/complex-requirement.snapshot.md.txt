# RepairDesk 复杂需求多代理声明

状态：active
负责人：Integration Lead / 集成负责人
适用范围：跨业务域、跨状态机或需要独立专业判断的 RepairDesk 需求规划、实现、审查与验收。
权威入口：本声明与 [`AGENTS.md`](../AGENTS.md)、[`AI智能部门管理/部门化管理设计.md`](../AI智能部门管理/部门化管理设计.md) 共同构成项目规则；执行路由见 [`.agents/README.md`](../.agents/README.md) 与 [`.agents/skills/agent-team-compose/SKILL.md`](../.agents/skills/agent-team-compose/SKILL.md)。

本声明解决一个运行问题：老板只需要用自然语言描述目标，主代理负责恢复上下文、形成可测合同、选择最小充分的专业视角、冻结范围并安排唯一写入者。它不要求老板填写模板，也不把部门标签冒充真实生成的 Agent。

## 1. 默认流程

复杂需求按下列顺序执行：

1. 自然语言入口：接收老板目标、限制、期望结果和不可触碰边界。
2. 2–4 个互补只读视角独立分析：按需选择产品流程、数据/API、UX/前端、安全、QA、发布或文档视角；每个视角必须有独立问题、证据和交付物。
3. 主代理提炼 3–5 个真实冲突：只记录会改变状态规则、数据来源、权限/隐私、金额、兼容性、发布或验收的冲突；不把意见差异堆成无意义辩论。
4. 仅在存在分歧或高风险时做一次交叉质疑：每个质疑必须指向具体方案、证据、严重度和可验证的解决方式。
5. 主代理记录采纳/拒绝：注明采纳依据、未采纳原因、残余风险和需要 Owner 决定的事项。
6. 冻结可测合同：明确状态机、输入输出、权限、非目标、回滚、测试和停止条件；合同冻结后不得由执行 Agent 擅自扩大。
7. 单一 Luna writer 实施：只有被授权的一个写入者修改业务代码或文档；文件所有权必须不重叠，审查 Agent 默认只读。
8. 独立 QA/安全/数据按风险复核：只读复核真实变更和证据，不自行重写范围。
9. Integration Lead 集成与最终门禁：只有集成负责人可以决定整合、提交、推送、部署或关闭任务，并保留证据、回滚点和记忆检查点。

## 2. 何时触发复杂模式

满足任一条件即可触发 T2/T3 复杂模式：

- 需求属于 T2/T3，而不是单文件文案、局部样式或一次性只读问答；
- 跨越两个或以上业务域（例如库存 + 订单、客户 + 权限、售后 + 支付）；
- 包含四个或以上业务状态、状态转移、合法下一步或终态；
- 涉及数据模型、权限、金额、客户隐私、生产行为或外部系统；
- 存在两个或以上合理方案，且取舍会影响兼容性、风险或后续迁移；
- 同时要求手机、桌面、列表、详情或其他多端交互验收；
- 需要独立 QA、安全、数据、架构或发布判断。

以下情况保留普通任务轻量策略：简单文案、局部样式、单文件低风险修复、明确且不可拆分的顺序阻塞动作。是否触发复杂模式由主代理根据风险和独立交付物判断，不由老板填写内部字段。

## 3. 团队边界与数量

- 通常生成 2–4 个互补只读 Agent；最多 5 个活跃 Agent（含写入者），除非项目规则另有更严格限制。
- 复杂模式至少需要一名唯一 Luna writer；不得让两个 Agent 同时改同一文件或同一目录范围。
- QA、安全、数据、架构和发布视角默认只读；发现问题回报 Integration Lead，不自行扩大权限。
- 如果没有独立交付物、任务只有一个不可拆分动作、工具不可用、存在秘密/生产权限风险、会造成写入冲突，或启动成本明显高于收益，可以不 spawn。此时必须在任务记录、证据、检查点和最终报告写明具体 `no-spawn reason`，并说明是主线程执行、模拟审查还是延期；“已考虑某部门”不等于“已生成 Agent”。
- 不允许无限递归委派、无限增加角色或为了“意见一致”反复辩论。完成合同验收、无 P0/P1 未解决问题、残余风险已记录，即达到停止条件。

## 4. 权限、生产与数据边界

多代理流程不扩大老板未授予的权限。默认禁止生产发布、数据库迁移/回填、凭据读取、客户完整 PII、支付写入和不可逆删除；这些动作仍须遵守项目既有批准门禁。Context Packet、任务记忆、截图和日志不得保存秘密、完整客户 PII、付款逐笔或不必要标识。绑定身份、生成 Agent 或获得 scoped write 并不等于获得集成、提交、推送、部署、迁移或生产权限。

## 5. 停止、证据与回滚

任务停止条件是：可测合同的验收项已满足；定向测试、必要的全量/发布候选检查和独立风险复核已有可追溯证据；没有未处置的 P0/P1；残余风险、未运行验证、Plan Delta 和回滚点已交给 Integration Lead。若条件未满足，保持任务进行或明确阻塞，不用继续扩大讨论代替实施证据。每个重大阶段保留精确文件、命令结果、截图（如有页面）、版本/分支和可回滚基点。

## 6. 老板自然语言示例

老板可以直接说：“把库存状态做成手机和桌面都能看懂的生命周期视图，默认不要误报在售，先给我安全的 Release A，售后只能走合法下一状态，并把测试和截图做完。”

这句话已经足够作为入口；系统会自动判断复杂度、恢复项目规则、组织互补视角、冻结合同和安排执行。老板无需知道 Agent 名称、内部模板、窗口 ID 或部门编号。
